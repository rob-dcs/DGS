Agent Tree anatomy

Every part of the Agent Tree, with its role, size and token. Hover a row in a legend to outline the part in the specimen. The Captain starts every agent. The tree groups the agents by task, one column for each task, on a canvas with a dotted grid. The page can also show a real run (Part 10). The failed count opens a list (Part 11).

Part 1

Agent card

One card per agent. A container holds the card and, under it, the meta row. The card is the same for the Captain, a worker and a reviewer. Only the avatar letter color, the name and the model change.

    Part 2

    Card surface states

    The card uses the Chip surface from the DCS Harness UI Kit. It has four states and a click effect. Hover a card in the specimen to see the real hover.

      Part 3

      Tree and summary bar

      The summary bar counts all agents. The Captain starts every agent. The tree groups them by task, with one column for each task. Bezier wires join the cards. The Captain's cost includes every column.

        Part 4

        Canvas, grid and drag

        The tree sits on an infinite canvas with a dotted grid. A card moves with the cards that hang on it, and lands on the grid. Try it: drag a card in the specimen.

              Part 9

              Behavior

              Cost rollup

              A card with children shows its own cost plus the cost of every descendant. A card without children shows only its own cost.

              Time

              A leaf shows its run time. A branch shows the time from its start to the latest end in the branch.

              Live update

              Each tick changes text only. The elements stay in place, so hover, focus and a drag do not break when an agent starts or finishes.

              Folding

              The fold button and the folded line both toggle the branch. Focus returns to the fold button after a toggle.

              Grouping by task

              The Captain starts every agent. The tree puts the agents of one task in one column. The first agent of the task heads the column.

              Running tasks

              The wire into a task is lit while that task has a running agent. A finished head card stays lit while a reviewer under it runs. When no agent runs, no wire is lit.

              Wires

              A script measures the cards and draws one bezier curve for each card. The curves follow a card while it moves, tilts or grows. A ring dot that a moved card covers is hidden.

              Running shine

              A running agent has a line and an orchid inner glow that travel round its edge. They fade at both ends and have grain. Each card starts at its own point. A card that stops running loses the shine.

              Cards appear when the Captain starts an agent

              A task that waits in dcs has no card. A card exists only for an agent that the Captain has started.

              New card

              A new child card comes out from behind its parent. It starts hidden behind the parent card, at scale 0 and opacity 0, with its centre on the parent's centre. In 650 ms it moves into its place while it grows and fades in. Its opacity is full at 70% of the motion. While it moves, it is under every other card. The wire to the card fades in with it. The Captain has no parent, so it only grows from 94%.

              Wire stability

              The page measures a new card at the end of its entrance, so a wire ends where the card will stop. It changes wires in place and does not rebuild them, so no wire jumps or flickers when a card appears.

              Selected state

              The Root card becomes selected when the user expands the Captain branch. It stays selected until the user folds the branch.

              Moving cards

              A head card moves its column. The Captain moves everything. Any other card moves alone. The move is in world units, so it is right at any zoom.

              Accessibility

              The tree uses role="tree". Each card is a treeitem with the name and status in its label. A branch has aria-expanded. Moving a card needs a pointer for now.

              Motion

              The spinner, the card entrance, the wire comet, the running shine, the click effect and the lift stop when the viewer asks for reduced motion.

              Part 10

              Live data

              The page can show a real run. A local server reads the Claude Code session in a repo and sends the page the whole list of agents every 2 seconds. Opened from a file, the page runs the demo instead.

                run, live, seq, tsThe run id, whether the Captain still works, a counter that grows when the agents change, and the time of the poll.
                id, parentIdThe agent and who started it. Only the Captain has no parent.
                taskIdThe dcs task, such as t2. The Captain puts it first in the agent description. It decides the column. An agent with no task id hangs on the Captain.

                statusRunning, Done, Failed or Needs input. A finished agent has the status of its own last reply: failed and blocked show as Failed, needs_input as Needs input. A reply that is not dcs JSON counts as Done.

                cost, costFinalDollars from the tokens in the transcript. Final only after the agent stops. A model with no price gives no cost.

                Where the data comes from

                The Agent Monitor library lists the agents. The dcs task store gives the task states. The transcripts give the times and the tokens. The page changes none of them.

                Task ids

                This page and the demo show ids such as t-02. A live run shows the dcs ids, such as t2. The adapter reads both forms as t2.

                Failed and Needs input

                Both come from what the agent says when it stops. The dcs failure count is not used: in real runs a worker stopped with the count still at 0.

                Privacy

                The server listens on this computer only and refuses any other host name. Recorded runs hold real task names and costs. Keep that folder out of a shared or synced location.

                Part 11

                Failed list

                The failed count in the summary bar is a button. It opens a list with one row for each failed agent. The tree is read-only, so a row can show the card and dismiss the entry. It cannot retry the task.

                  ActionWhat the page does
                  Click the countOpens or closes the list. The chevron turns, and aria-expanded follows.
                  Show cardPans the canvas so that the card of that agent is in the centre.
                  DismissRemoves the row and lowers the count. The card keeps its Failed status. The list closes when no row is left.
                  Escape, or a click outsideCloses the list. Escape returns focus to the count.
                  A long reasonShows four lines. The tooltip holds the full text.
